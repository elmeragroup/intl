`extract --watch` syncs on a save to a catalog however `catalogs` spells its path. A save to a catalog an absolute pattern reaches with `..` (`/app/messages/jump/../{locale}.po`, with `jump` a link, or `/app/messages/missing/../{locale}.po` once `missing` is created) ran no sync in either mode: the watch named the saved file by the pattern's lexical spelling, which is another file. Neither did a save to a catalog whose file name the config spells in another case than the disk, on a volume that folds case. The watch now takes a change for a catalog when its file is that catalog, as the catalog import does, resolving the catalogs again after each sync, and watches a catalog spelled with `..` where the kernel takes it. A catalog that is a file link (`messages/nb.po -> ../translations/nb.po`) is watched on native events in its target's directory too, that directory alone and only where it can be watched, so a save to the target syncs, and a file an editor renames over the link is still the catalog; and a watched tree that lies under a link inside another (`src/linked -> ../feature` inside `src`) keeps its own native watch, which the outer tree's does not deliver for. A save to a PO that is no configured catalog still runs no sync, and a config that worked before writes and prints what it did.
