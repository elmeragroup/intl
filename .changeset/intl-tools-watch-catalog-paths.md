`extract --watch` recognises a save to a catalog by the file it is, as the catalog import does, however `catalogs` spells its path. A save to a catalog spelled with `..` in an absolute pattern (`/app/messages/jump/../{locale}.po`, with `jump` a link, `/app/messages/sub/../{locale}.po`, or `/app/messages/missing/../{locale}.po` once `missing` is created), with `./` or a doubled separator, or with its file name in another case than the disk on a volume that folds case, ran no sync, because the watch compared the changed path with the pattern's spelling, and named a change in the directory it watches as `messages/jump/..` by collapsing the `..`, another file than the one the kernel reported. It now names that change where the kernel climbs to, and compares identities. The catalogs' identities are resolved again after each sync, and a changed file named like a catalog that they miss is checked against the disk, so a deleted catalog is still that catalog, a file an editor's atomic save renamed over a catalog's file link is that catalog, and the file a repointed link left behind is no longer one. A save to a PO that is no configured catalog still runs no sync. The directories the watch listens to are unchanged: a catalog whose real directory no watched tree covers (for example one whose `..` climbs through a link that did not resolve as the watch started, one whose `..` is spelled under an include root and climbs out of it through a link, or, on native events, a file link to a file elsewhere) still gets no change event.
