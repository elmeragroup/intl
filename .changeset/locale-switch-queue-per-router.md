- `useLocaleSwitch` (`/next`, `/start`) keeps one switch queue per router, shared by every mount under it, as its documentation said: a switcher may mount anywhere and any number of times, and a switch held in a switcher that unmounted still yields to a newer one from the next, so the latest switch wins across remounts. On Next the queue belongs to `router.refresh` (Next's own navigator, so every App Router in a page shares it); on Start, to the router object. `isPending` is router-wide for switches: a client-rendered switcher mounted while another's switch is held shows it from its first commit (a hydrating one, from the commit after), and server renders show `false`. Each switch calls the `persist` its mount last committed under the router that admitted it, when the switch starts, published as the commit lands (before its layout effects, and also inside a hidden `<Activity>`), so a switch released from any effect of the commit that changed it calls the new one; a switch queued before its mount moved to another router persists and refreshes through the router that admitted it. On Next a switch reads `persist` and the `refresh` option from the same commit, so a mount that changed mode while a switch was queued refreshes when its new persist needs it. A mounted switcher keeps only what it committed under its current router, and what a queued switch still needs. A `router.refresh()` that throws now resolves the switch `RefreshFailed` (it resolved `Switched` and threw in the switcher's next render), and one that throws during a failed persist's recovery counts as a failed refresh, so the next failed persist still re-renders the stored locale. Mounts with different Next refresh modes share the queue: when a `"server-action"` switch's persist fails after a `"router-refresh"` switch stored a locale it never rendered, the failing switch's own refresh renders it. An app that lifted the hook into one shared provider to get one queue can call it in each switcher instead.
- `createLocaleSwitcher` (`/core`) is unchanged: each call makes its own queue, and calls the port's methods on the port.
