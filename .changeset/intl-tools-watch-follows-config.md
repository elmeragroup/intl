`elmera-intl extract --watch` follows an edit of `elmera-intl.json`. Before, it kept the config it read at its start until it was restarted, and printed nothing about the change. Now a change of the config's text prints `elmera-intl.json changed, restarting the watch` and restarts the watch on the config as edited, so a new locale gets its catalog and a changed `include` or `catalogs` is synced. A config edited into an invalid one stops the watch and prints its problem; the edit that fixes it starts the watch again. A restart whose watch fails to start prints a `WatchFailed` problem, and the next edit retries. The watch reads the config again every 250 ms, or every `--poll` interval, so any edit is followed, a repointed or restored symlink included; an edit made while the watch starts is followed once that start ends, and the last of several quick saves wins. Ctrl-C exits clean at any moment, during a start or while the watch waits on an invalid config. A Ctrl-C while the operating system holds the config's read (a hung network mount) stops the watch at once, but the process exits when that read returns; a second Ctrl-C ends it at once. A watcher that fails to close as the watch stops is now reported once, not also again by its `done`.
