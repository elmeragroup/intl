A config reached through a link to its directory means one thing to every tool. Its root is now the real path of the directory its path names, so `extract`, `check`, the watch, `intl()` and `withIntl` resolve every relative path in it, `formats` as well as `catalogs`, from one place: with `/mnt/web -> /repo/apps/web`, `"../messages/{locale}.po"` in `/mnt/web/elmera-intl.json` is `/repo/apps/messages` for each, where `withIntl` and the catalog import looked in `/mnt/messages` and `extract --config /mnt/web/elmera-intl.json` wrote there. The real path is the one Next and Vite resolve: the kernel's on POSIX, so a directory spelled in another case on a volume that folds case, or a link whose target climbs with `..` through another link, roots where the kernel and the hosts put it, and Node's own resolution on Windows, which keeps a mapped drive. Each read of the config takes its text and its root from one directory, so a link repointed during the read never pairs one checkout's config with another's root. An absolute `catalogs` pattern climbing out of a link with `..` is read where the kernel takes it by `withIntl`'s rule and the catalog import too, as `extract` writes it. An absolute pattern whose `..` follows a directory that does not exist, which `extract` refuses (`CatalogClimbsMissing`), is no catalog to the import either. `extract --watch` restarts when a link to the config's directory is repointed, the config's text unchanged, and names what it writes from the new root. A symlinked `elmera-intl.json` keeps the directory its link is in as its root, as before. `withIntl` also takes the app directory at its real path, as Next's CLI does (`next dev`, `next build`, `next start`): with `dir` a link straight to a workspace app and no root set, its rule now matches the catalogs below the workspace root Next uses, and with `next` hoisted to the workspace, the PO loader still gets Turbopack's roots, where it got none and checked nothing. A custom server's `next({ dir })` takes `dir` as given, which `withIntl` cannot see: give it the app's real directory.

Before the first `extract` after upgrading, a project whose `catalogs` climbs with `..` from a directory reached through a link should compare the directory its catalogs were written in with the one they resolve to now, and move or merge its translated PO files there: `extract` writes a new PO where none is, and a newly extracted PO cannot recover the translations left in the old one. Printed paths, and the absolute paths scripts read from `extract --json` or from the watch's output, now use the real spelling (`/private/tmp` for `/tmp` on macOS). To give two directories that link to one app their own siblings, make each a real directory holding a symlinked `elmera-intl.json`.
