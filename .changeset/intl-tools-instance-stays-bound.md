---
"@elmeragroup/intl-tools": minor
---

Extraction and the `elmera-intl/extractable` lint rule fail an IntlInstance used as a value in the file that binds it ([#40](https://github.com/elmeragroup/intl/issues/40)). Before, a page could hand its instance to a child (`<Row intl={intl} />`), and a child that does not import `@elmeragroup/intl` read `const { t } = intl` unchecked: its messages were silently left out of the catalogs and shipped untranslated, with `check` green. Now an instance bound from `useIntl()`, `getIntl()`, `createIntl()` or `yield* CurrentIntl` may only be read through its own members (`t`, `format`, `locale`, `timeZone`, `catalog`, `formats`), bound by a declaration that is not exported, cleared by a plain assignment (`intl = undefined`; a compound one, `intl ??= other`, reads it and fails), listed in a dependency array, spread into an object (`<Row {...intl}>` under the automatic JSX runtime, or given as the props of a `createElement` bound to a `react` import, which copies them), or discarded (`await getIntl();`, `void getIntl()`). The failure is at the parent, names the expression (`intl`, `useIntl()`, `createIntl(…)`, `yield* CurrentIntl`) and the fix. The files that receive an instance read as before.

Code that extraction used to accept now fails. Each form, and its rewrite:

- an instance passed as a JSX prop (`<Row intl={intl} />`) or a call argument (`formatDue(intl, d)`, `render(yield* CurrentIntl)`): call `useT()` or `useIntl()` in the child, or pass `intl.format`, `intl.locale` or `msg()` descriptors;
- a context value (`<Ctx.Provider value={intl}>`, an outlet's `context={intl}` or `context={{ intl }}`): render `<IntlProvider {...config}>`, nested where a child needs another locale, and call `useIntl()` or `useT()` in the child;
- an instance stored in state, a ref or an object (`setI(createIntl(cfg))`, `useState([intl])`, `r.current = intl`, `box.intl = intl`, a request context `{ intl: createIntl(cfg) }`): store the config, and call `createIntl(config)` where it is used;
- an instance returned (a local factory, `useMemo(() => createIntl(cfg), [cfg])`): render `<IntlProvider>` and call `useIntl()`, or return the config;
- an instance exported (`export const intl = createIntl(cfg)`, `export { intl }`, `export default intl`): export the config, and call `createIntl(config)` where it is used;
- an instance passed as the props of a hand-written `jsx(Row, intl)` (from `react/jsx-runtime`, which keeps the object itself as the props): pass `{ ...intl }` if the child needs the config;
- an instance as a JSX child (`<Box>{intl}</Box>`): render a member (`{intl.locale}`), or bind it in the child;
- an instance chosen rather than bound (`cached ?? createIntl(cfg)`, `x ? await getIntl() : undefined`, `x ?? useIntl()`, a pattern default such as `function f({ intl = createIntl(cfg) })`), which now fails at the factory's call even when only a member such as `.locale` is read (a `.t(…)` on the result already failed as untraced): choose the config first, then bind (`const intl = createIntl(cached ?? cfg)`);
- an instance on the right of a plain assignment (`let i; i = createIntl(cfg)`): bind it in the declaration, `const i = createIntl(cfg)`;
- an instance logged, compared or inspected (`console.log(intl)`, `intl === other`, `typeof intl`, `!intl`, `` `${intl}` ``, `intl.valueOf()`, `intl.toString()`): compare or log a declared member (`intl.locale`);
- an instance given to `Object.assign` (`Object.assign({}, intl)`): `{ ...intl }` is the copy; given to `Object.values` or `Object.entries`: read the member by name;
- `.then`, `.catch` or `.finally` on an un-awaited `getIntl()` (`getIntl().then(…)`, `getIntl().catch(…)`, `const p = getIntl(); p.then(…)`), or `getIntl()` inside `Promise.all`: `const intl = await getIntl()`, or a helper that awaits it and returns the member it needs (`async function money() { const { format } = await getIntl(); return format; }`, then `const [format, data] = await Promise.all([money(), load()])`);
- an instance passed to an Effect layer or service (`Layer.succeed(CurrentIntl, createIntl(cfg))`, which already failed at `CurrentIntl`): `CurrentIntl.layer(options)` or `CurrentIntl.provide(effect)`;
- a factory's call in a dependency array (`useEffect(f, [useIntl()])`): bind it, then list `[intl]`.

Tests and stories fail too: `elmera-intl/extractable` runs on every file it lints, test files that `include` leaves out as well. `renderHook(() => useIntl())` returns the instance from the callback, so it now fails at `useIntl()`: return the member the test needs (`renderHook(() => useIntl().locale)`). A unit test that hands `createIntl(cfg)` to a component (`render(<Row intl={createIntl(cfg)} />)`) renders the component inside `<IntlProvider {...cfg}>` instead, and the component calls `useIntl()` or `useT()`.

Under the classic JSX runtime, `<Row {...intl}>` with the spread as its only attribute compiles to `factory(Row, intl)`, handing the factory the instance itself. React's `createElement` copies the props, so the spread passes when the factory is bound to a `react` import (`import React from "react"`), and under the automatic runtime it compiles to a copy and passes. It now fails, where it passed before, in the two configurations that need the `@jsxRuntime classic` pragma and name another factory: `React` as a global (`/** @jsxRuntime classic */` with no `react` import), and a `@jsx` factory such as preact's `h` (`/** @jsxRuntime classic */ /** @jsx h */` with `import { h } from "preact"`), where the extractor cannot prove the factory is React's, and a factory that keeps the object by reference (as React 19's own `jsx()` does) gives the child its `t` unextracted. Neither is a supported setup (the React peer is `^19.0.0`, which needs the automatic runtime; preact is not a peer). The failure names the rewrite: copy it yourself, `<Row {...{ ...intl }}>`, or use the automatic runtime (or import `React`). Extraction reads a file without the pragma as the automatic runtime, whatever the build is configured with.

`[t]` and `[intl]` are a dependency array by one rule, by how the hook is bound. A hook bound to a `react` import (named, renamed, or `React.x` through React's default or namespace import) is one only for `useEffect`, `useLayoutEffect`, `useInsertionEffect`, `useMemo`, `useCallback` and `useImperativeHandle`, at their dependency argument, the last: so `React.useEffect(f, [t])`, `React.useCallback(f, [t])` and `import { useMemo as memo } from "react"; memo(f, [t])` now pass. Any other bare `use*` callee is one when it is called with two or more arguments, the array last, as before, so a custom effect hook (`useAsync(f, [t])`) keeps passing. Newly failing, each with `` `t` is passed or stored `` (or the instance message for `[intl]`):

- `[t]` or `[intl]` in a single-argument `use*` call (`useState([t])`, `useRef([t])`, `useEffect([t])`): state is not a translator's place; put a dependency array at the dependency argument;
- in React's `useState`, `useReducer` (`useReducer(r, [t])`) or `useRef`, renamed or not (`import { useState as useS } from "react"; useS(0, [t])`);
- at the wrong slot (`useImperativeHandle(ref, [t])`): put it at the dependency argument;
- in a member facade (`Hooks.useEffect(f, [intl])`, which `[t]` already failed): call React's hook, or `useCallback(f, [t])` and pass the facade `[cb]`.

A bare `use*` callee not imported from `react` that keeps its last argument (a custom hook such as `useStore(cb, [intl])`, a React hook re-exported through an app module, `preact/hooks`) still passes, and a `{ t }` read from what it keeps, in a file that does not import the package, extracts nothing: the README lists it as a residual. Closing it would fail every custom effect hook, and closing it after 1.0 would be a breaking change.

A specifier of `export … from "…"` and `export * as name from "…"` name the other module's binding, so `export { t as x } from "./other"` and `export * as t from "./other"` beside a bound `t` in the same file no longer fail. `export { t }` of a bound `t` now reports once, as ``exporting `t` hides its call sites``, not twice. `import.meta` and `new.target` are no longer read as a binding named `meta` or `target`, so `const meta = useT()` beside `import.meta.url` no longer fails as `` `meta` is passed or stored ``.
